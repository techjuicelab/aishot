# AIShot 1.11 검증 기록

- 대상: 1.11 / build 16, macOS 14 이상, Apple Silicon·Intel universal.
- 검증 환경: macOS 27.2.1 (26B131), 실제 사용 중인 맥. 입력은 CGEvent로 합성했다.
- 사용자 요청: Dropover를 목적지로 고르면 shelf로 받고 싶다. "Dropover shelf에도 넣기"
  체크박스와 shelf에만 넣는 옵션을 원한다. 스크린샷 텍스트 복사가 잘 안 된다.

## 1. 텍스트 복사가 "안 되던" 문제

### 원인 — 첫 인식 22초

로그상 실패는 없었다. 22:00:28에 저장된 캡처가 22:00:50에야 클립보드에 들어갔고, 같은
파일을 다시 인식하면 0.5초였다. 그 사이에 붙여넣으면 이전 클립보드가 들어가 "안 되는"
것으로 보인다.

Vision의 텍스트 모델은 `~/Library/Caches/<번들 ID 또는 실행 파일 이름>/com.apple.e5rt.e5bundlecache/<macOS 빌드>/`
아래에 컴파일돼 캐시된다. AIShot의 캐시 폴더는 22:00에 처음 만들어졌고, 1.10.2 검증 때
macOS는 26B123, 지금은 26B131이다. 측정:

| 조건 | 첫 인식 |
|---|---|
| 새 이름의 실행 파일(같은 바이트를 다른 경로에 복사해도) | 20.1–21.4초 |
| 같은 이름의 두 번째 프로세스 | 0.13초 |
| 같은 이름에서 바이너리만 바꿈 | 0.17초 |
| 빈 이미지로만 예열한 뒤 새 프로세스에서 2열 페이지 | 0.86초 |

캐시 키는 번들 ID(또는 실행 파일 이름)와 macOS 빌드다. 앱 업데이트로는 무효화되지 않고
macOS 업데이트 뒤 첫 인식만 느리다. 인식기를 메뉴 막대 호스트 안에서 쓰면 160MB가 계속
남아(빈 이미지 예열만은 24–39MB) 호스트 상주 방식은 쓰지 않았다.

### 수정

- 호스트가 시작 5초 뒤 `--warm-ocr` 단기 프로세스로 빈 이미지를 한 번 인식한다(nice 10,
  2초를 넘기면 로그). 메모리는 프로세스와 함께 반환된다.
- 인식이 0.8초를 넘기면 "텍스트 인식 중… 잠시만 기다려 주세요" HUD를 띄우고, 끝나면 기존
  완료 HUD로 바꾼다.

### 원인 — 읽는 순서

- 2열(두 요금제 카드) 페이지가 "Google AI Pro / Google AI Ultra / 5TB / 20TB …"로
  한 줄씩 섞였다. 기존 코드는 위에서 아래로 정렬해 한 관찰을 한 줄로 출력했다.
- 화면에 없는 줄: 가장자리에 닿은 첫 줄 위에 신뢰도 0.30의 "넹. 가능합니다._"가 겹쳐
  나왔다(진짜 줄은 1.00).

### 수정 — `TextLayout.swift`

중복 제거(더 확실한 줄과 작은 쪽 면적의 50% 이상 겹치면 버림) → 열(아무 줄도 가로지르지
않는 세로 틈, 단어 간격보다 넓은 1.5줄 높이 이상) → 띠(가장 넓은 가로 틈, 그 90% 이상인
틈에서 한 번에) → 행. 양쪽 행이 70% 이상 맞으면 표·양식으로 보고 행으로 읽되, 양쪽 모두
10줄 높이보다 넓고 줄바꿈된 문장이 있으면 열로 본다(두 카드는 행 84%가 맞아 행 기준만으로는
표와 구분되지 않았다). 같은 행의 조각은 공백, 2줄 높이보다 넓은 간격은 탭으로 잇고, 문단
간격(0.65줄 높이 초과)과 열 전환에는 빈 줄을 넣는다.

`RecognizeDocumentsRequest`(macOS 26+)는 열 순서는 맞았지만 한국어 인식이 나빠지고
("요금게", "져정용정", "Google2| d|0|E& 718") 한 장에 40초가 걸려 쓰지 않았다.

### 검증

- `tests/text-layout`: 표, 2열 본문, 중복 줄, 좁은 사이드바, 라벨+값 양식, 같은 행 조각,
  문단 7/7 통과.
- 실제 캡처: 터미널(중복 줄 사라짐, 문단 빈 줄 원문과 일치), 2열 요금제 페이지(카드 단위로
  읽힘), 텔레그램 대화 목록(이름+시간 한 줄, 대화마다 빈 줄), 예약 화면, 5K 화면 0.73초.
- 설치본에서 모델 캐시를 옆으로 옮기고 호스트를 재시작: 5초 뒤 예열 시작, 21.1초 뒤
  `ocr: text recognizer prepared in 21.1s`, 캐시 재생성.
- 새 이름 실행 파일: 예열 없이 `--deliver --ocr` 22.2초(3초 시점 진행 HUD 표시 확인) /
  `--warm-ocr` 21.7초 뒤 같은 작업은 인식 1초 미만.
- 실제 ⌘⇧1 + 합성 드래그(설치본 1.11): 캡처 저장 23:21:40 → 복사 23:21:40, 공개 빌드에서
  23:25:11 → 23:25:12. 1.10.2에서는 22초.

### 범위 밖으로 남긴 것

스크롤 캡처의 큰 타일(폭 2244px에서 높이 3590px)에서 Vision이 짧은 줄을 놓친다. 같은
화면을 40번 이어 붙인 35,760px 이미지에서 "추가가 필요합니다." 줄이 40번 중 12번만
인식됐고, 1.10.2 코드도 똑같다. 타일 크기 조정은 별도 측정이 필요하다.

## 2. Dropover shelf

### 전달 방식

| 방식 | shelf | 포커스 |
|---|---|---|
| 파일을 Dropover로 백그라운드 열기(`open -g -a`, NSWorkspace activates=false) | 생성 | 유지(Safari·Ghostty) |
| "Add to Dropover" 서비스(NSPerformService) | 생성 | Dropover로 바뀜 |

백그라운드 열기를 쓴다. 새 shelf로 열지 떠 있는 shelf에 쌓을지는 Dropover의
`InboundItemsDistribution`(Settings → Shelf → Adding Files Behavior)을 따른다. 기본값은
새 shelf이고, `visibleShelf`로 잠시 바꾸자 두 번째 파일이 기존 shelf에 쌓였다(창 수 그대로,
shelf에 이미지 2개). 확인 후 값을 지워 기본값으로 되돌렸다.

### 수정

- 목적지 목록 맨 아래 "Shelf — 붙여넣지 않고 shelf에만 담기" 구역에 Dropover shelf(별칭
  `dropover`). 붙여넣기 없음, 클립보드 유지. Dropover에 닿지 못하면 클립보드 복사.
- "Dropover shelf에도 넣기"(`dropoverAlso`): 설정 체크박스와 메뉴 막대 항목. 붙여넣기
  구간의 모든 종료 지점을 `finishDelivery()`로 모아, 붙여넣기 뒤에도, 클립보드 복사로 끝난
  경우에도 shelf에 담는다. Dropover가 설치돼 있을 때만 보인다.
- 설정 창은 체크박스 한 줄만큼 28pt 키웠다.

### 검증

- 빌드 트리 실행 파일 `--deliver --target dropover`: shelf 생성, Ghostty 최전면 유지,
  클립보드 해시 동일.
- `dropoverAlso` + `--no-paste`: 경로가 클립보드에, shelf 생성. 설정과 클립보드는 원복.
- 설치본에서 목적지 Dropover shelf + 실제 ⌘⇧2 + 합성 드래그: iCloud Drive 스크린샷 폴더의
  파일이 shelf로 들어감, Ghostty에 붙여넣지 않음, 클립보드 동일. 목적지는 Ghostty로 원복.
- 메뉴 막대 메뉴(접근성 트리): 목적지 하위 메뉴 끝에 Shelf 구역과 Dropover shelf, 메인
  메뉴에 "Dropover shelf에도 넣기".
- 설정 창 화면: 새 체크박스가 겹침 없이 들어감.

시험으로 생긴 shelf는 모두 닫았고, 시험 캡처는 스크린샷 폴더에서 치웠다.

## 3. 서명과 배포

이 맥의 로그인 키체인에는 서명 인증서가 없었다(1.10.2 인증서는 11-08 다른 맥에서 만듦).
1Password Private의 "TechJuice Local Code Signing (macOS code signing identity)"에서
.p12를 `op read`로 파이프해 가져오기 프로그램에 넘기고, 비밀번호는 `op run`이 그 프로세스의
환경 변수로만 넣었다(디스크·명령 인자·출력에 남지 않음). 접근 허용 목록에 codesign을 넣었고,
공개 인증서를 코드 서명용으로 신뢰했다. SHA-1 `E1220384…` 일치,
`security find-identity -v -p codesigning`에 1개.

Sparkle EdDSA 키는 "Sparkle EdDSA private key (TechJuice Mac apps)"의 `key.txt`를
`SPARKLE_ED_KEY_OP`로 넘겼다.

| 배포 파일 | 바이트 | SHA-256 (앞 16자) |
|---|---:|---|
| AIShot-1.11.zip | 3645851 | `5e648b2ed16ebdcc` |
| AIShot.dmg | 3929694 | `c29919ff68f32eca` |

- 드라이런: `codesign --verify --deep --strict` 통과, 지정 요구사항
  `certificate leaf = H"e1220384de3731eda34cd68d8cc2a4d53f958182"`, 1.11 (16), x86_64·arm64.
- 공개 후: 버전별 ZIP·DMG와 `latest` DMG를 인증 없이 내려받아 모두 HTTP 200, appcast의
  길이·SHA-256과 일치. 앱의 `SUPublicEDKey`로 CryptoKit Ed25519 검증 통과, 1비트 변조본 거부.
  ZIP과 DMG의 앱 파일 트리 해시 동일(`8c9a174d…`), `latest`와 버전별 DMG 동일.
- 이 맥의 설치본은 공개 ZIP으로 교체했고 파일 트리 해시가 같다. 인증서가 같아
  `signing identity unchanged — existing permissions kept`, 권한 재허용 없이 실제 단축키 동작.

## 범위

물리 키보드·마우스 대신 합성 입력을 썼고, 물리 Intel Mac 검증과 Sparkle을 통한 1.10.2 →
1.11 실제 자동 업데이트(이 맥은 설치 스크립트로 교체)는 하지 않았다.
