# AIShot 1.10.1 설치 회귀 검증

- 대상: 1.10.1 / build 14, macOS 14 이상, Apple Silicon·Intel universal.
- 루트와 독립 하위 에이전트 3개, 총 4개 에이전트를 동시에 운용했다.
- OCR와 내장 단축키 기능은 1.9·1.10의 구현을 유지한다.

## 발견한 오류

실제 1.9 → 1.10 설치에서 Sparkle가 인자 없이 다시 실행한 기존 메뉴 호스트가 남았다.
설치 코드는 LaunchAgent와 `--menubar` 프로세스만 종료했으므로, 이전 호스트가 메뉴 잠금을
계속 보유해 새 LaunchAgent가 시작한 호스트가 즉시 종료했다. 설치 실패를 확인한 뒤 커널 잠금 소유자와
실행 명령을 대조해 이전 호스트만 종료하고 새 호스트의 정상 실행을 확인했다.

## 1차 — 원인과 수정 검토

메뉴 잠금 파일의 `F_GETLK` 결과로 실제 소유 PID를 조회한다. `proc_pidpath`의 실행파일이
`AIShot.app/Contents/MacOS/AIShot`이고 명령이 그 경로 단독 또는 정확한 `--menubar`일 때만
종료한다. 잠금 소유자가 `--settings`, 캡처 작업이나 다른 실행파일이면 유지하며 설치를 중단한다.
종료 직전 소유자를 다시 확인하고 종료 후 잠금 해제까지 검사한다.
기존의 명시적 `--menubar` 수동 호스트 정리도 실행파일과 명령을 검증하면서 유지한다.

## 2차 — 독립 회귀 검증

- 구현 담당의 임시 프로세스 검증 16항목 통과. 실제 C 실행파일을 가짜 `AIShot.app`에 배치해
  인자 없음·정확한 `--menubar`의 종료와 커널 잠금 해제를 확인했다.
- 독립 안전성 검증 24항목 통과. 실제 Python 잠금 보유자를 생산 코드로 식별하고 외부 프로세스는
  종료하지 않음을 확인했다. 주입한 프로세스 연산으로 인자 판정·종료·잠금 해제를 추가 확인했다.
- 다른 독립 회귀 검증 21항목 통과. 1.10 원본 코드는 인자 없는 임시 호스트의 잠금이 남은 채
  성공을 반환해 결함을 재현했고, 수정 코드는 같은 조건에서 잠금을 해제했다.
- 세 검증은 독립 임시 프로세스·잠금만 사용했다. 캡처·OCR·스크롤·설정·다른 실행파일·추가 인자,
  심볼릭 링크 거부, 종료 실패와 제한된 대기 등 경계를 각각 검증했다. 항목 간 중복은 있다.
- `/tmp`와 `/private/tmp`의 경로 별칭 차이는 검증 실행파일의 `argv[0]`를 실제 경로로 맞춰
  처리했으며, 제품의 정확한 실행 명령 검증 범위를 넓히지 않았다.

## 3차 — 배포 패키지 검증

격리 소스에서 `./release.sh 1.10.1 --dry-run`을 완료했다. ZIP과 읽기 전용 DMG의 101개
파일·심볼릭 링크가 일치하며 양쪽 모두 엄격한 전체 아키텍처 코드 서명 검사를 통과했다.
실제 1.9 백업 앱의 공개키를 기준으로 CryptoKit Ed25519 검증과 변조 거부를 확인했다.
appcast의 파일 길이·SHA-256·서명이 패키지와 일치한다. 버전은 1.10.1/build 14이고,
arm64·x86_64의 최소 macOS는 모두 14.0이다.

ZIP에서 직접 추출한 실행파일의 CLI 14건을 다시 통과했다. 내장 단축키·OCR·설정 UI·이전
구현이 1.10 검증 소스와 같음을 확인해 기존 native 37건, UI 10건, 한영 화면 4개의 증거를 유지한다.

## 4차 — 공개 배포와 실제 설치

기존 앱·설정·Karabiner 원본을 백업했다. 실제 설치된 1.10 앱을 Sparkle 재실행 표식으로
인자 없는 메뉴 호스트로 띄워 커널 잠금 소유와 정확한 실행 경로를 확인한 뒤, ZIP에서 추출한
1.10.1의 `--install`을 실행했다. 종료 코드 0, 기존 인자 없는 호스트 종료, 새 LaunchAgent의
실행과 새 PID를 확인했다. 설치된 실행파일은 검증된 패키지와 바이트가 같다.

설정은 한국어·Ghostty 목적지·저장 위치 등을 유지했고, 비교에서 달라진 항목은 Sparkle의
`SULastCheckTime`뿐이다. 임시 재실행 표식은 소비됐으며 Karabiner 파일도 재설치 전후 같다.
기존 화면 기록·손쉬운 사용 권한이 유지됐고, 실제 설정의 단축키 탭에서 기본 2/8/1과
정상 앱 아이콘을 확인했다. 창은 값을 저장하지 않고 닫았다.

GitHub 태그 `v1.10.1`은 소스 커밋 `204fd94bfc78d03c3daedf12a79dc54cdf67d213`을 가리킨다.
공개된 버전별 ZIP·DMG와 `latest` DMG를 인증 없이 내려받아 모두 HTTP 200, 위 표의 길이와
SHA-256, 기존 공개키 기준 Ed25519 서명을 재검증했다. `latest`와 버전별 DMG는 동일하다.
자동 업데이트 피드는 1.10.1/build 14를 첫 항목으로 제공한다.

## 범위

단축키·OCR·설정 UI의 기존 검증 범위는 [1.10 검증 기록](1.10-validation.md)과 같다.
물리 키보드로 영역을 선택해 세 캡처를 완료하는 전체 흐름과 물리 Intel Mac 검증은 포함하지 않는다.
