# AIShot 1.11.1 검증 기록

- 대상: 1.11.1 / build 17, macOS 14 이상, Apple Silicon·Intel universal.
- 검증 환경: macOS 27.2.1 (26B131), 실제 사용 중인 맥.
- 사용자 보고: 맥을 재시작할 때마다 AIShot이 캡처를 시작한다. 로그인 시 실행은 원하지만
  재시작 직후 캡처는 필요 없다.

## 원인

2026-11-15 09:03 재시작 로그:

| 시각 | 출처 | 내용 |
|---|---|---|
| 09:03:15.393 | launchd | LaunchAgent `space.techjuicelab.aishot.menubar`가 `--menubar` 호스트 실행 |
| 09:03:15.834 | loginwindow | `performAutolaunch, launching: /Applications/AIShot.app` (Login Items → Open at Login) |
| 09:03:16 | `/tmp/aishot.log` | 호스트 시작 직후 캡처 저장 |

AIShot이 LaunchAgent와 Open at Login 양쪽에 등록돼 있었다. Open at Login 항목은 앱이
추가하지 않는다(코드에 등록 경로 없음). 호스트가 경쟁에서 이기면 인자 없는 두 번째 실행은
"호스트 실행 중 + 인자 없음 = 1회 캡처"로 처리됐다. 순서가 반대면 두 번째 실행이 호스트가
되고 LaunchAgent 쪽은 "menu bar is already running"으로 0 종료하므로 문제 없다.

## 수정

- loginwindow는 open-application Apple event에 `keyAEPropData = keyAELaunchedAsLogInItem`
  (`'lgit'`)을 붙인다. 인자 없는 실행이고 호스트가 떠 있으며 호스트 시작 후 120초 안일 때만
  이 이벤트를 읽고, 로그인 항목이면 로그를 남기고 0 종료한다.
- 이벤트를 받는 데 새 프로세스에서 약 0.1초(NSApplication 0.065초 + 첫 이벤트 0.03초)가
  걸린다. 외부 실행기의 인자 없는 캡처가 이 시간을 매번 쓰지 않도록 호스트 시작 직후로 한정했다.
- README·README.ko에 예외 동작과 Open at Login이 필요 없다는 안내를 추가.

## 검증

사전 측정(별도 시험 앱, `NSWorkspace.OpenConfiguration.appleEvent`로 로그인 항목 이벤트 재현):

| 실행 방식 | `lgit` | 이벤트 도착 |
|---|---|---|
| `open -gn` ×3 | false | 0.095–0.099초 |
| 로그인 항목 이벤트 ×3 | true | 0.100–0.106초 |
| 실행 파일 직접 실행 | false (AppKit이 빈 oapp 합성) | 0.090초 |

설치본 시험(`settings` 잠금을 잡아 캡처 UI가 뜨기 직전 단계에서 멈추게 함):

1. 호스트 시작 6초 뒤 로그인 항목 이벤트로 실행 → "opened as a login item … nothing to
   capture", screencapture 없음. 1.11.1 릴리스 zip(GitHub 자산과 SHA-256 일치)으로 설치한
   뒤 재확인도 같은 결과.
2. 호스트 시작 직후 `open -gnb space.techjuicelab.aishot`(Karabiner 방식) → 확인 통과 후
   캡처 단계 도달("settings are open — ignored capture trigger").
3. 호스트 시작 125초 뒤 로그인 항목 이벤트로 실행 → 확인을 건너뛰고 캡처 단계 도달(기존 동작).

이 맥에서는 Open at Login의 AIShot 항목을 지운 뒤 실제 재시동했고(09:15), 호스트만 시작되고
캡처 기록은 없었다. 항목을 다시 넣은 상태의 실제 재시동은 해 보지 않았다. loginwindow가
붙이는 표시는 위 재현으로만 확인했다.
