# AIShot 1.9 OCR 복사 검증

- 대상: 1.9 / build 12, macOS 14 이상, Apple Silicon·Intel universal.
- 구성: 루트 에이전트와 독립 하위 에이전트 3개, 총 4개를 동시에 실행.
- 기능: 메뉴의 **스크린샷 텍스트 복사…** 또는 `--ocr`로 영역을 캡처하고 한국어·영어 텍스트만 복사.
- 사용자 클립보드·목적지·Karabiner 활성 설정·설치본은 검증 중 변경하지 않았다.

## 1차 — 독립 코드 검토

OCR·타일링, CLI·메뉴·클립보드, 문서·단축키, 빌드·릴리스를 병렬 검토했다.
고정 14px 허용치로 y/x를 선택하는 정렬 비교식이 비추이적이라는 문제를 확인했다.
배포 스크립트에도 릴리스 태그의 대상을 전체 커밋 SHA로 고정했다.

## 2차 — 실제 엔진과 복사 흐름

생산 `ScrollCapture.swift`를 직접 링크한 Vision 하네스로 혼합 언어, 코드, 작은 글자,
어두운 배경, 좁은 영역, 빈 이미지, 다단 배치, 타일 경계를 검사했다.
12px 글자·14px 줄 간격·교차 들여쓰기에서 6줄의 순서가 뒤바뀌는 문제를 재현했다.

별도 배송 하네스는 임시 main 복사본에서 캡처 입력·pasteboard·설정·로그·권한 전제와 HUD를
격리하고 일반 라우팅 호출 여부를 계측했다. Ghostty/path·pasteSubmit·returnFocus를 켠
상태를 포함한 성공 4건과
취소·빈 결과·시간 초과·잘못된 이미지·인자 충돌·출력 불가 등 10건을 통과했다.
보존 검사는 문자열뿐 아니라 PNG·파일 URL과 pasteboard changeCount까지 비교했다.

## 3차 — 수정 후 회귀·빌드

정렬을 엄격한 y 우선 정렬, 글자 높이에 따른 고정 기준 행 묶기,
행 안의 x 우선 정렬로 변경했다.

- 이전 순환 사례 6개, 동일 행 조각 24개, 들여쓰기 6행 720개: 총 750개 입력 순열이 동일한 순서를 반환.
- 실제 12px·14px 들여쓰기, 4개 타일의 경계, 폭 200·300·1200px 각 40줄, 혼합 언어·빈 영역: 8건 원문 일치.
- 추가 10종 OCR 회귀에서도 앱의 줄 순서·중복·누락 문제 없음.
- 최신 소스로 배송 14건 재실행 통과. 실제 HUD를 표시한 성공·빈 결과 2건도 통과.
- arm64·x86_64 최적화 빌드, `codesign --verify --deep --strict`, shell·JSON·diff 문법 검사 통과.

## 4차 — 배포 패키지

격리한 소스 복사본에서 `./release.sh 1.9 --dry-run`으로 ZIP·DMG를 만들었다.
패키지는 사용자 설치본에 설치하지 않고 검사했다.

- ZIP·DMG: 1.9/build 12, 동일한 앱 식별자·업데이트 공개키, arm64·x86_64 실행파일.
- 코드 서명 검증과 appcast의 URL·파일 길이·SHA-256 일치 검사.
- Sparkle 도구와 독립 CryptoKit 구현으로 서명 검증. CryptoKit은 기존 설치본의 공개키를 사용했으며 변조된 서명·본문은 거절.
- 패키지 실행파일의 OCR 복사 전용 self-test, 일반 이미지·경로 라우팅과 충돌 인자 검사.

## 검증 범위와 한계

실제 Apple Vision을 사용한 이미지·배송 검증이며, 사용자 화면에서 영역을 직접 드래그하는 UI 검증이나
물리 Intel Mac 검증을 대신하지 않는다. Intel 실행파일은 교차 빌드·아키텍처 검사로 확인했다.
원래 클립보드는 유지하기 위해 배송 하네스에서 별도 이름의 pasteboard를 사용했다.

작은 글자에서 `AIShot`을 `AlShot`으로 읽거나 코드의 공백·문장부호를 다르게 읽는
Vision 인식 오차가 남는다. 코드 문법·들여쓰기를 복원하는 기능은 제공하지 않는다.
새 바이너리의 최초 인식에서는 AppleNeuralEngine 모델 컴파일 중 22~47초 대기를 관측했다.
동일 바이너리의 다음 새 프로세스에서는 첫 인식 약 0.2~0.4초, 10종 전체 약 1.6초였다.
이는 매 캡처마다 반복되는 지연으로 재현되지 않았다.
