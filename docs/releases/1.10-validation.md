# AIShot 1.10 내장 단축키 검증

실제 설치에서 발견한 기존 호스트 종료 오류는 [1.10.1 검증 기록](1.10.1-validation.md)에
기록하고 수정했다. 1.10 자동 업데이트 피드는 공개하지 않았으며 1.10.1로 제공한다.

- 대상: 1.10 / build 13, macOS 14 이상, Apple Silicon·Intel universal.
- 루트와 독립 하위 에이전트 3개, 총 4개 에이전트를 동시에 운용했다.
- 기본값: 일반 스크린샷 `⌘⇧2`, 스크롤 스크린샷 `⌘⇧8`, 텍스트 복사 `⌘⇧1`.
- Karabiner 없이 메뉴 막대 호스트가 단축키를 직접 등록한다.
- 설정의 **단축키 탭**에서 녹화·해제·기본값 복원을 선택하고 저장한다. 취소는 기존 값을 유지한다.

## 1차 — 설계·독립 리뷰

메뉴 호스트만 키를 등록하고 설정창도 같은 프로세스에서 연다. 녹화 중에는 등록을 중지하고,
저장·취소 후 복구한다. 별도 `--settings` 실행은 호스트에 창 열기를 요청하고 응답을 받는다.
호스트가 응답하지 않아도 살아 있다면 독립 녹화창을 열지 않으며, 부재가 확인된 경우에만 별도 창을 사용한다.

설치된 SDK와 실제 시스템 목록으로 확인한 결과, 기본 등록 옵션은 다른 앱과 중복을 허용하므로
`kEventHotKeyExclusive`와 `CopySymbolicHotKeys`를 함께 사용했다.
현재 검증 Mac은 `⌘⇧6`뿐 아니라 `⌘⇧7`도 예약 중이어서 최종 기본값을 `⌘⇧8`로 정했다.
시스템 단축키 설정은 변경하지 않았다.

## 2차 — 등록·녹화·이전 기능

- 생산 `Hotkeys.swift`를 직접 링크한 37항목 통과: 기본 3키 실제 등록·해제, 중복·시스템 충돌,
  일반 문자 입력 보호, 키 반복 방지, 세 동작 콜백, 저장 실패 복구, 일시 중지·복귀, 재로드,
  명시적 비활성화와 기본값 구별, 키보드 레이아웃 표시, 객체 종료 시 등록 해제.
- 생산 UI와 실제 모델을 연결한 10개 시나리오 통과: 명령 키 조합 녹화, Esc 취소, Delete 해제,
  복원, 중복·예약 키 거부, Tab/Return/Space 처리, 등록 오류 안내, 기능 키 허용.
- 이전 하네스 통과: AIShot 기본 조합만 제거, 사용자 조합·조건부 조합·다른 앱 동작·양쪽 Shift 보존,
  혼합 규칙 보존, 백업 바이트·권한 확인, 1회 적용, JSON 오류·백업 실패·symlink·동시 변경 시 원본 보존.

이전은 새 내장 키를 등록할 수 있을 때만 수행한다. 기존 AIShot 기본 Karabiner 규칙 1/2/6을
정확히 식별하며, 전체 원본을 `~/Library/Application Support/AIShot/Backups`에 먼저 보관한다.
백업 파일은 0600, 백업 폴더는 0700이며 실제 원본 바이트를 다시 확인한 뒤 교체한다.
명시적 설치뿐 아니라 Sparkle 업데이트 후 호스트 시작과 최초 등록 충돌 해소 후 저장에서도
같은 이전 함수를 호출한다. 완료 표식을 사용해 반복 이전하지 않는다.

## 3차 — 수정 후 회귀·UI

리뷰 중 발견한 설정 창의 참조 순환을 weak 캡처로 수정했다. AppKit 하네스에서 창과 편집기의
해제를 확인했다. 응답 지연 시 호스트와 별도 편집기가 충돌하는 문제와 중복 창 요청도 보완했다.
별도 창은 편집 종료까지 호스트 잠금을 유지하며, 외부의 예전 AIShot 캡처 명령도 편집 중에는 무시한다.

일반·단축키 탭의 한국어·영어 네 화면을 자체 검증 창으로 렌더했다.
영문 창은 584×589pt, 한국어 창은 584×573pt로 모든 조작 버튼과 안내문이 잘림 없이 표시됐다.
검증용 F17/F18/F19 조합은 별도 테스트 도메인에서만 사용했고, 해당 테스트 앱과 설정은 정리했다.

arm64·x86_64 최적화 빌드와 전체 타입 검사, shell·JSON·diff 문법 검사를 통과했다.
기존 OCR·이미지·터미널 경로 전달에 필요한 모드와 CLI 조합도 다시 확인했다.

## 4차 — 배포 패키지

격리 소스에서 `./release.sh 1.10 --dry-run`으로 ZIP과 DMG를 생성했다.
두 패키지의 앱·실행파일·메타데이터를 대조하고 엄격한 코드 서명을 검사했다.
기존 설치본의 공개키로 Ed25519 서명을 독립 검증했으며 변조한 서명·본문은 거절됐다.
appcast의 버전·빌드·URL·파일 길이·SHA-256과 실제 자산을 비교했다.
ZIP 내부 실행파일의 CLI 검증 14건을 통과했다.

## 범위

등록 API는 실제 OS를 사용했고, 반복·콜백 검사는 Carbon 이벤트를 격리 주입했다.
물리 키보드 입력부터 실제 화면 영역 선택·세 캡처 완료까지의 전체 실사용 검증은 별도다.
Intel은 교차 빌드·아키텍처 검사이며 물리 Intel Mac 검증은 포함하지 않는다.
OCR 엔진 자체의 작은 글자·문장부호 인식 한계는 1.9와 같다.
