# AIShot 1.10.2 검증 기록

- 대상: 1.10.2 / build 15, macOS 14 이상, Apple Silicon·Intel universal.
- 검증 환경: macOS 27.2 (26B123), 실제 사용 중인 맥. 입력은 CGEvent로 합성했다.
- 사용자 증상: 스크린샷이 가끔 씹히거나 들어가지 않는다. 특히 Muse에 잘 안 들어가고,
  ⌘⇧2 뒤 드래그가 안 될 때가 있다.

## 1. 드래그가 안 되던 문제

### 원인

`screencapture -i`는 선택 화면이 뜬 뒤 시작된 드래그만 받는다. 그 전에 시작한 드래그는
아래 창이 받고, 캡처는 아무것도 선택되지 않은 채 남아 Esc로 끝난다(로그의
`nothing captured (screencapture exit 0)`). 1.10.1은 단축키마다 작업자 앱을 먼저 실행한
뒤 screencapture를 띄워, 단축키부터 screencapture 시작까지 따뜻할 때 50–100ms, 한동안
쉬었다가 처음 찍을 때 300–400ms가 걸렸다. 선택 화면 자체도 부하에 따라 50–300ms가 더
걸린다.

같이 확인한 사실(순수 screencapture, 합성 입력):

| 조건 | 결과 |
|---|---|
| ⌘⇧를 캡처 전부터 누른 채 드래그 / 뗀 뒤 드래그 | 7/7 캡처 |
| ⇧만 누른 채 드래그 | 3/3 캡처 |
| 캡처 도중 ⌘를 새로 눌렀다 뗌(마우스와 무관) | 세션이 이후 모든 드래그를 무시 |
| 선택 화면이 뜨기 전 드래그 | 실패 |

캡처 도중 ⌘를 새로 누르는 경우는 정상 사용에서 생기지 않아 이번 범위에서 다루지 않았다.

### 수정

- 메뉴 막대 호스트가 screencapture를 직접 띄운다(`RegionCapture.swift`). 저장·붙여넣기는
  `--deliver` 작업자가 맡는다.
- 캡처 초반 2초 동안 필터 이벤트 탭으로, 선택 화면 전에 시작된 드래그를 아래 창에
  보내지 않고 붙잡는다. 드래그가 끝나고 선택 화면이 150ms 이상 떠 있으면 탭을 제거한 뒤
  같은 사각형을 합성 이벤트로 다시 그린다. 선택 화면을 끝내 식별하지 못해도 1초 뒤에는
  다시 그린다.
- 탭을 남긴 채 다시 그리면, 같은 스레드의 필터 탭이 합성 이벤트를 붙잡았다가 15ms
  안에 몰아서 전달해 클릭으로 처리됐다(캡처 없이 종료). 그래서 다시 그리기 전에 탭을 뗀다.

### 검증

트리거 후 0·10·30·50ms에 시작한 드래그:

| 빌드 | 캡처 |
|---|---|
| 1.10.1 (설치본, 작업자 경유) | 0/4 |
| 1.10.2 세션 (호스트 경로와 같은 구동) | 4/4 |

선택 화면 뒤 250·400·700ms 정상 드래그 3/3, ⌘⇧를 누른 채 드래그 2/2,
선택 화면 직후 드래그 1/1 모두 캡처(회귀 없음).

## 2. Muse에 들어가지 않던 문제

### 원인

Muse(com.meta.endo 11.1)의 입력창은 WKWebView 안에서 `Message · Attach file · Send`
하나의 버튼으로 노출되고, 실제 편집기는 접근성 트리에 없다. 편집기에 포커스가 없으면
⌘V를 받고도 버린다. 1.10.1 로그는 이때도 `pasted image into Muse`라고 기록했다.

| 조건 | 첨부 |
|---|---|
| 편집기 포커스 없음 (현재 형식 1회, 이미지 데이터만 1회, 검색칸에 포커스 1회) | 0/3 |
| 입력창 버튼에 AXPress / AXFocused 후 | 0/2 |
| 입력창 가운데 클릭 — 첨부로 커진 상태라 썸네일 줄에 떨어짐 | 0/1 |
| 편집기 포커스 확보 후 (iCloud 파일 URL·/tmp 파일 URL·이미지 데이터만) | 4/4 |

- AXPress는 `Attach file`과 같아 파일 선택 창이 열린다(확인 후 취소). 사용하지 않는다.
- AXFocused는 바깥 컨테이너에만 포커스 링이 생기고 편집기는 여전히 포커스가 없다.
- 첨부가 있으면 입력창이 위로 커지므로, 가운데가 아니라 맨 아래 텍스트 줄을 클릭해야 한다.
- 참고: WebKit은 클립보드에 파일 URL이 있으면 이미지 데이터 대신 그 파일을 읽는다.
  Muse는 iCloud Drive의 스크린샷을 읽을 수 있어 형식은 바꾸지 않았다.

### 수정

붙여넣기 전에 창 하단 220pt 안에서 가장 아래의 넓은 버튼(입력창)을 위치로 찾아,
맨 아래 텍스트 줄(오른쪽 끝에서 140pt, 아래에서 29pt)을 클릭하고 포인터를 되돌린다.
그 지점의 요소가 Muse 소유인지 먼저 확인한다. 로그는 `sent image paste (⌘V) to Muse`로
바꿨다.

### 검증

수정 코드(`--deliver`)로 포커스를 뺀 Muse에 첨부: 앞에 있을 때 1/1, Finder 뒤에 있고
기존 첨부로 입력창이 커진 상태 1/1. 테스트 첨부는 모두 제거했다.

## 3. 설치·호스트 복구

- App Translocation: 실제 위치를 `SecTranslocateCreateOriginalPathForURL`로 해석하고,
  교체는 옆에 복사를 마친 뒤에만 한다. 임시 폴더 단위 테스트 12/12(신규·업그레이드·원본
  없음·자기 자신 위 복사·잔여물 없음).
- 인자 없는 실행: 설치본에서 호스트를 종료한 뒤 `open -b space.techjuicelab.aishot`
  → 캡처 없이 `starting the host`로 메뉴 호스트가 시작됨을 확인했다. 확인 후 LaunchAgent로
  되돌렸다(`state = running`).

## 4. 서명 인증서 교체

1.10.1을 서명한 자체 서명 인증서(leaf `009d748a…`)는 예전 개발 맥에만 있었고 남아 있지
않았다. 같은 이름의 새 자체 서명 인증서(SHA-1 `E1220384…`, 2036-11-05까지)를 만들어
로그인 키체인에서 코드 서명용으로 신뢰하고, .p12와 1Password가 생성한 비밀번호를
1Password Private 금고에 백업했다(다시 내려받아 바이트·지문 일치 확인). Sparkle EdDSA
키는 바꾸지 않았고, 1Password의 키가 앱의 `SUPublicEDKey`와 짝임을 공개키 계산으로
확인했다. 배포는 `SPARKLE_ED_KEY_OP`로 키를 1Password에서 표준입력으로 넘겼다.

Sparkle 2는 EdDSA 키를 유지하면 Apple 코드 서명 인증서 교체를 허용한다
(`SUUpdateValidator`: 제거는 거부, 교체는 허용).

## 5. 배포 패키지

드라이런과 공개 후 각각 확인했다.

- `codesign --verify --deep --strict` 통과, 지정 요구사항
  `certificate leaf = H"e1220384de3731eda34cd68d8cc2a4d53f958182"`.
- 1.10.2 (15), arm64·x86_64, 최소 macOS 14.0. ZIP과 DMG의 앱 내용 동일.
- 공개 ZIP·버전별 DMG·`latest` DMG를 인증 없이 내려받아 모두 HTTP 200, appcast의 길이·
  SHA-256과 일치. 앱 공개키로 CryptoKit Ed25519 검증 통과, 1비트 변조본은 거부.
  `latest`와 버전별 DMG 동일.

| 배포 파일 | 바이트 | SHA-256 (앞 16자) |
|---|---:|---|
| AIShot-1.10.2.zip | 3591169 | `7e2becdb0296351e` |
| AIShot.dmg | 3585304 | `c52ffdfa74782e9e` |

## 6. 실제 업데이트와 최종 확인

- 이 맥의 1.10.1이 앱 안의 Sparkle로 1.10.2를 받아 설치했다. 옛 호스트가 재실행 표식을
  남겼고, 새 호스트가 `relaunched by the updater`로 떴으며, 인증서 변경을 감지해
  `permissions were reset once`를 기록했다. 설치본은 공개 ZIP과 바이트 단위로 같다.
- 사용자가 화면 기록·손쉬운 사용을 다시 허용한 뒤, 실제 단축키로:
  - ⌘⇧2 + 트리거 84ms 뒤 드래그(새로 띄운 호스트의 첫 캡처라 screencapture는 341ms에
    시작): 부모 프로세스가 호스트임을 확인, 드래그를 다시 그려 저장, 포커스 없는 Muse에 첨부.
  - ⌘⇧2 + 선택 화면 뒤 드래그(데워진 호스트: screencapture 79ms, 선택 화면 151ms),
    Muse가 Finder 뒤·포커스 없음: 첨부.
  - ⌘⇧1: 21자 인식·복사. 인식은 캡처 후 약 14초 걸렸는데, 같은 파일의 Vision 첫 실행이
    12.6초(두 번째 0.05초)로 시스템 부하 중 모델 로딩 비용이다. 1.10.1도 매번 새 프로세스에서
    인식했으므로 회귀가 아니다.
- 테스트로 생긴 스크린샷 3개와 Muse 첨부는 지웠고, 클립보드는 원래 텍스트로 되돌렸다.

## 범위

물리 키보드·마우스 대신 합성 입력을 썼고, 물리 Intel Mac 검증은 하지 않았다. 캡처 도중
⌘를 새로 누르면 screencapture가 이후 드래그를 무시하는 동작은 그대로다. 텍스트 인식의
첫 실행 지연을 줄이려면 인식을 상주 호스트로 옮기는 별도 작업이 필요하다.
